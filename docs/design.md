# Taskline タスク管理アプリ 設計書

## 0. 設計思想

本プロジェクトでは、

「AIを利用して開発を行うこと」

と

「AIをアプリの機能として組み込むこと」

を明確に区別する。

本プロトタイプは、
AIをアプリの機能として利用する体験を目的として作成する。

また、同一のプロトタイプを複数チームが改良し、

- どのような発想が生まれるか
- AIをどのように活用するか
- どのようなユーザー体験を提供するか

を比較・共有することを目的とする。

---

## 1. 概要

本アプリは、タスクの登録・管理・進捗確認を行うWebアプリである。
SQLiteによる永続化とGeminiによるタスク作成・検索・分析支援を提供する。

---

## 2. プロジェクト目的

本プロジェクトでは、

AIを利用してアプリを開発すること

ではなく、

AIをアプリの機能として組み込むこと

を体験する。

また、

同一のプロトタイプを複数チームが改良し、
どのような発想やAI活用が生まれるかを比較する。

完成度や実装量だけではなく、

- AI活用方法
- 設計方針
- ユーザー体験

の違いを共有することを目的とする。

---

## 3. 想定ユーザー

社内メンバー

例

- 開発者
- リーダー
- 若手社員

実運用を前提としない。

---

## 4. 機能範囲

- タスクの登録・一覧・詳細・編集・削除
- ステータス、優先度、期限日、担当者の管理
- キーワード検索、条件フィルター、一覧ソート
- 完了日時の記録、タスクごとのコメント・作業メモ
- 総数とステータス別件数のダッシュボード
- Geminiによる自然文タスク作成・検索、優先度提案、進捗分析、ダッシュボード分析、チャット
- SQLiteへの永続保存

ユーザー認証・権限管理、外部ストレージ連携は対象外とする。

---

## 5. システム構成

### 利用技術

- Python / Flask
- SQLite
- HTML / CSS / JavaScript / Jinja2
- Google Gemini API（`google-genai`）

### データ

- タスク: 名前、詳細、担当者、優先度、ステータス、期限、作成・更新・完了日時
- コメント: タスクID、本文、作成日時
- 既定のDBファイル: `instance/tasks.sqlite3`。`TASK_DATABASE`で変更可能

---

## 6. 基本動作

利用者はWeb画面からタスクを登録・検索・更新し、アプリはSQLiteへ保存する。
AI機能は `prompts/system_prompt.txt` と機能別指示を組み合わせてGeminiを呼び出す。
入力は2000文字以内、アプリから返す生成文は5000文字以内に制限する。
指定モデルが503を返した場合は `gemini-3.8-flash` で1回だけ再試行する。

---

## 7. プロンプト方針

AIへの指示は

prompts/system_prompt.txt

で管理する。

ソースコードへ直接記載しない。

プロンプトは成果物として扱う。

チームごとの工夫や改善点を比較するためである。

また、

AIの人格

AIの役割

AIの回答方針

は system_prompt.txt に定義する。

最終発表では以下を比較対象とする。

## 10. プロトタイプ完成条件

- タスクCRUD、検索・フィルター・ソートが動作する
- ステータス別集計、コメント、完了日時が記録される
- SQLiteに保存されたデータがアプリ再起動後も保持される
- Geminiの作成支援・検索・分析・チャットを利用できる
- Gemini APIキー未設定でも基本的なタスク管理を利用できる
